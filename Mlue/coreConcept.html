Core computer science concepts behind Mlue

Each challenge connects an e-commerce task to a data structure or algorithm. The dashboard currently runs challenges 1, 2, 5, and 10. The remaining entries describe the project roadmap and display an “Under Construction” panel in the workspace.

Implemented in the dashboard

These algorithms are connected to working controls and produce results in the workspace.

Challenge 01 · Searching

Binary search and sorted arrays

Implemented

Problem: Find products closest to a target price without comparing every item on every search.

How it works: The catalog is sorted once by price. Binary search narrows to the target's insertion point; two pointers then expand from the nearest price, choosing whichever side is closer until three products are collected.

Cost: Initial sort is O(N log N); each query takes O(log N + K), where K is the number of results. The sorted copy uses O(N) space.

Challenge 02 · Priority queues

Min-heap for Top K

Implemented

Problem: Rank products by a popularity score without sorting the whole catalog.

How it works: Popularity is rating × review count. A min-heap holds at most K candidates, keeping the least popular candidate at its root. A new product replaces the root only when its score is higher; the retained products are then returned in descending order.

Cost: O(N log K) time and O(K) heap space, plus O(K log K) to drain and order the results.

Challenge 05 · Hash maps and collaborative filtering

Co-view frequency recommendations

Implemented

Problem: Suggest products that shoppers viewed alongside a selected product.

How it works: The app finds simulated browsing sessions containing the selected item, counts every other product in those sessions with a hash map, and sorts candidates by co-view count. A second map resolves product IDs to product data.

Cost: If H is the number of session-view entries and M is the number of distinct co-viewed products, the current scan and sort take O(H + M log M) time and O(M) additional space. The browsing histories are sample data.

Challenge 10 · Optimization

0/1 knapsack dynamic programming

Implemented

Problem: Choose products with the highest total value while staying within a warehouse weight limit.

How it works: For each product and each capacity, a DP table compares leaving the item out with including it (if it fits). Backtracking through the table recovers the selected products. Each product can be selected at most once.

Cost: O(N × W) time and space for N products and capacity W. Product weights are estimated by category/name; values use catalog prices.

Roadmap concepts

These topics are introduced on the home page, but their interactive implementations are not yet connected to the dashboard.

Challenge 03 · Cache design

LRU cache: hash map + doubly linked list

Roadmap · Not implemented

A hash map locates a cached product quickly, while a doubly linked list tracks recency. A product visit moves its node to the most-recent end; when capacity is reached, the least-recent node is evicted. Lookup, refresh, and eviction can each be O(1).

Challenge 04 · State history

Two stacks for undo and redo

Roadmap · Not implemented

The undo stack stores prior cart states and the redo stack stores states reversed by an undo. Undo and redo move the current state between stacks; a new cart edit clears redo history. Push and pop are O(1), excluding the cost of copying a cart snapshot.

Challenge 06 · Range queries

Prefix sums and range data structures

Roadmap · Not implemented

A prefix-sum array stores cumulative inventory values, so a static range total can be calculated by subtracting two prefix values in O(1) after O(N) preprocessing. If values must change frequently, a tree-based structure such as a segment tree supports updates and range queries in O(log N).

Challenge 07 · Prefix search

Trie (prefix tree)

Roadmap · Not implemented

A trie stores product-name, brand, or tag characters along paths from the root. Searching follows the characters typed so far, then gathers matching products below that prefix node. Finding the prefix takes O(L) for a prefix of length L; output collection depends on the number of matches.

Challenge 08 · Weighted graphs

Dijkstra's shortest-path algorithm

Roadmap · Not implemented

Warehouses and delivery hubs can be modeled as vertices, with route distances or costs as non-negative weighted edges. Dijkstra's algorithm repeatedly settles the nearest reachable vertex and relaxes its neighbors, tracking predecessors to reconstruct the best route. With a min-priority queue, the usual bound is O((V + E) log V).

Challenge 09 · Dependency ordering

Topological sort and cycle detection

Roadmap · Not implemented

Represent each prerequisite as a directed edge in a dependency graph. A topological ordering lists each dependency before the item that requires it. Kahn's algorithm repeatedly removes zero-in-degree nodes; if nodes remain when no such node exists, the graph contains a cycle. The traversal takes O(V + E) time.
